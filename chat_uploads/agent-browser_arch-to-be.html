0. 설계 원칙

세 가지가 이 문서 전체를 관통합니다.

데몬은 정확히 1개, 격리 단위는 세션이다. agent-browser는 네임스페이스마다 데몬을 띄우므로, 네임스페이스를 서버 핀 1개로 고정합니다. 그 아래 작업마다 별도 Chrome(세션당 1개)이 붙고, 동시 호출은 서로의 탭/ref를 절대 건드릴 수 없습니다.

익명 호출을 금지한다. 매 호출마다 namespace+session을 명시하게 하고, 등록되지 않은 쌍은 실행하지 않습니다. 남의 live 브라우저에 몰래 붙는 일을 구조적으로 차단합니다.

돌아가는 것은 건드리지 않는다. 스위퍼·LRU는 in-flight 호출이 있는 세션을 절대 닫거나 퇴출하지 않습니다. 정리는 idle 세션에만 일어납니다.

1. 프로세스 토폴로지

opencode (MCP client, stdio) ── tools/list · tools/call (35 tools, JSON-RPC) │ ▼ mcp-server.mjs (proxy, node, 의존성 0) ── 레지스트리: ns+session → lastSeen/inFlight │ │ └─ 파일 저장 (재시작 내성, TTL 만료분 제외) │ 호출마다: 명시 검증 → ensure 확인 → CLI 단발 실행 → 결과 반환 (무상태) ▼ agent-browser CLI --namespace opencode --session <S> <cmd> --json (호출당 1프로세스) ▼ agent-browser daemon ×1 ── 데몬 1개가 전부 관리 (idle 15분이면 스스로 종료) │ ├─ Chrome (session: task-A) 작업 A 전용 ├─ Chrome (session: task-B) 작업 B 전용 (A와 간섭 불가) └─ Chrome (session: repo-aa …) 기존 세션과 동거 가능
핵심 제약: 프록시는 브라우저를 직접 소유하지 않습니다. 브라우저 생명주기의 진실의 원천은 agent-browser 데몬이며, 프록시는 호출 게이트 + 추적 + 정리만 담당합니다. 이 비대칭 덕분에 프록시가 죽거나 재시작돼도 실행 중인 브라우저는 영향받지 않고, 레지스트리 파일로 추적을 복원합니다.

2. 세션 생명주기

ensure (신규) ──▶ tracked ──▶ open/snapshot/click… (inFlight 카운트) │ │ │ ├─ 종료 시: close → untracked + 브라우저 종료 │ └─ 방치 시: TTL(10분) → sweeper가 close │ ensure (live 존재) ──▶ EXISTS + 탭 목록 ──▶ reuse:true ──▶ tracked (adopt) └─ 다른 이름 ──▶ 신규로 시작
확인 규칙: 데몬에 live 세션이 있는데 레지스트리에 없으면(프록시 재시작, 타 작업 소유) EXISTS 보고 + 탭 목록을 먼저 보여주고 reuse:true 확정 없이는 진입하지 않습니다. 미등록 쌍으로 도구를 직접 호출하면 ensure로 유도됩니다.

3. 호출 흐름 (도구 1회)

1. namespace 필수 확인 (핀값과 다르면 거부 + 안내)
2. session 필수·형식 확인 (한글 허용, default 거부)
3. needSession 도구: 레지스트리 등록 여부 확인 (미등록 → ensure 유도)
4. selector 자동 교정 (e12 → @e12)
5. CLI 단발 실행 (--namespace/--session/--idle-timeout 15m/--json, 타임아웃+kill)
   └ open 한정: 25초 초과 시 get_url로 검증 후 성공 보고 (콜드 기동 hang 흡수)
6. 실패 시 복구 힌트 첨부 (stale ref / tab_gone / covered / timeout)
7. inFlight 증감 + lastSeen 갱신 (finally 보장)

4. 한글 이름 인코딩

CLI·데몬은 소켓/경로 제약상 ASCII만 받습니다. 프록시는 사용자 표시명과 CLI 전달명을 분리합니다.

구분규칙예
사용자 입력 검증유니코드 문자·숫자·-_, 최대 64자결제-확인 허용
ASCII 통과그대로 전달 (가독성 유지)repo-aa → repo-aa
비ASCII 인코딩u + UTF-8 hex (초과 시 sha256 축약), 결정적결제-확인 → uebb2b0…ec9db8
표시 역변환레지스트리·저장 파일의 원본명으로 표시, session_list에 매핑注記u… = "결제-확인"

8. 알려진 이슈

세션당 첫 open 최대 ~35초: 브라우저 첫 기동 시 upstream open이 반환하지 않는 문제로, 프록시가 검증 후 성공 보고로 흡수합니다. 이후 호출은 1~2초입니다.
닫힌 세션명 잔류: session list에 닫힌 이름이 남을 수 있으나 upstream 기록 유지 동작이며, 브라우저 프로세스는 정리됩니다.
