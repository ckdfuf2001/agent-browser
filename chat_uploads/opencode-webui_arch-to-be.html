rev.2 · 전체 채팅 FTS 인덱싱 + 훅 게이트 리뷰 + git 커밋 척추 반영

기존 유지 기존 파일 수정 / 훅 추가 신규 (Hermes 이식) 신규 (git 인덱스 계열)

0. 설계 원칙

세 가지가 이 문서 전체를 관통합니다.

진실의 원천은 SQLite입니다. .memory/*.md는 프롬프트 주입을 위한 렌더 산출물일 뿐이고, 파일 flush는 session.idle에서만 일어납니다. Hermes의 "세션 시작 시점 스냅샷 고정" 의미론을 유지하면서 prefix cache 무효화를 막기 위함입니다.

인덱싱과 큐레이션은 트리거 정책이 다릅니다. 검색 인덱스는 전체 채팅을 예외 없이 삼킵니다 (비용 0, 프롬프트 미점유, 가치는 롱테일에 있음). 반면 프롬프트 예산 2,200자를 놓고 경쟁하는 코어 메모리 쓰기는 훅 이벤트로 게이팅합니다.

git은 검색의 척추, 세션은 거기 매달리는 살입니다. 커밋은 사람이 이미 선언한 경계라 청킹이 필요 없고 중복이 자연 제거됩니다. 대신 실패한 접근·폐기 이유·미커밋 작업은 git에 없으므로 세션 로그가 채웁니다.

3.2 신규 테이블

-- ── 코어 메모리 (Hermes 1계층) ──────────────────────────────
CREATE TABLE memory_entries (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  scope        TEXT NOT NULL,              -- 'user' | 'agent' | 'repo'
  repo_id      INTEGER,                    -- scope='repo'일 때만
  content      TEXT NOT NULL,
  source       TEXT NOT NULL DEFAULT 'agent',  -- agent | user | review
  session_id   TEXT,
  hit_count    INTEGER NOT NULL DEFAULT 0,
  last_used_at INTEGER,
  created_at   INTEGER NOT NULL,
  updated_at   INTEGER NOT NULL,
  archived_at  INTEGER,
  UNIQUE(scope, repo_id, content)
);
CREATE INDEX idx_mem_scope ON memory_entries(scope, repo_id, archived_at);

CREATE TABLE memory_pending (
  id         TEXT PRIMARY KEY,
  scope      TEXT NOT NULL,
  repo_id    INTEGER,
  action     TEXT NOT NULL,                -- add | replace | remove
  old_text   TEXT,
  content    TEXT,
  origin     TEXT NOT NULL,                -- review | agent
  session_id TEXT,
  rationale  TEXT,                         -- 왜 이걸 저장하려는지 (UI 표시용)
  status     TEXT NOT NULL DEFAULT 'pending',
  created_at INTEGER NOT NULL
);

CREATE TABLE memory_snapshots (            -- 세션 시작 시 고정된 렌더 결과
  session_id TEXT PRIMARY KEY,
  rendered   TEXT NOT NULL,
  char_count INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);

-- ── 세션 검색 (Hermes 3계층) · 전체 채팅 인덱싱 ─────────────
CREATE VIRTUAL TABLE session_messages_fts USING fts5(
  text,
  session_id UNINDEXED, message_id UNINDEXED, role UNINDEXED,
  repo_id UNINDEXED, turn_index UNINDEXED, ts UNINDEXED,
  tokenize='trigram'                       -- 한글 부분일치 필수
);

-- ── 훅 이벤트 (리뷰 게이트 + 스킬 승격 소스) ─────────────────
CREATE TABLE hook_events (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  repo_id    INTEGER,
  kind       TEXT NOT NULL,      -- command_run | bash_fail | git_commit | test_run
  name       TEXT,               -- 커맨드/스킬 이름
  exit_code  INTEGER,
  stderr_tail TEXT,              -- 마지막 2KB만
  cwd        TEXT,
  turn_index INTEGER NOT NULL,   -- 리뷰 컨텍스트 윈도우 중심점
  duration_ms INTEGER,
  reviewed_at INTEGER,           -- NULL이면 리뷰 대기
  created_at INTEGER NOT NULL
);
CREATE INDEX idx_hook_pending ON hook_events(session_id, reviewed_at);
CREATE INDEX idx_hook_promote ON hook_events(repo_id, kind, name, exit_code);

-- ── git 커밋 척추 ───────────────────────────────────────────
CREATE TABLE git_commits (
  sha          TEXT NOT NULL,
  repo_id      INTEGER NOT NULL,
  subject      TEXT NOT NULL,
  body         TEXT,
  author       TEXT,
  branch       TEXT,
  committed_at INTEGER NOT NULL,
  files_json   TEXT NOT NULL,    -- ["src/a.ts","src/b.ts"]
  insertions   INTEGER, deletions INTEGER,
  PRIMARY KEY (repo_id, sha)
);
CREATE INDEX idx_commit_time ON git_commits(repo_id, committed_at DESC);

CREATE VIRTUAL TABLE git_commits_fts USING fts5(
  subject, body, files,          -- diff 본문은 넣지 않음 (온디맨드)
  sha UNINDEXED, repo_id UNINDEXED, committed_at UNINDEXED,
  tokenize='trigram'
);

CREATE TABLE commit_sessions (             -- 척추 ↔ 살 조인
  repo_id      INTEGER NOT NULL,
  sha          TEXT NOT NULL,
  committed_at INTEGER NOT NULL,           -- rebase/squash 후 sha 소실 대비 fallback 키
  session_id   TEXT NOT NULL,
  turn_start   INTEGER, turn_end INTEGER,
  PRIMARY KEY (repo_id, sha, session_id)
);
CREATE INDEX idx_cs_fallback ON commit_sessions(repo_id, committed_at);

CREATE TABLE repo_index_state (            -- 증분 인덱싱 커서
  repo_id       INTEGER NOT NULL,
  branch        TEXT NOT NULL,
  last_sha      TEXT,
  last_indexed_at INTEGER,
  PRIMARY KEY (repo_id, branch)
);

4. 통합 후 요청 흐름 시퀀스

세 흐름 모두 하나의 규칙을 공유합니다. DB 쓰기는 즉시, 파일 flush는 지연. Hermes는 run_agent.py 안에서 시스템 프롬프트를 직접 조립하므로 "세션 시작 시점 고정"이 자연히 성립하지만, 여기서는 OpenCode가 instructions[]의 파일을 읽습니다. 파일을 언제 쓰느냐가 곧 스냅샷 의미론이 됩니다.

4.1 세션 시작 → 메모리 주입 (frozen snapshot 재현)

Browser 세션 생성 요청 │ ▼ Backend /api/session (proxy.ts) │ │ ① directory → repo_id 해석 (repos.local_path 매칭) │ │ ② flush barrier 검사 │ SELECT count(*) FROM session_status │ WHERE directory=? AND status != 'idle' │ ├─ 0건 → snapshot-renderer 실행 (안전) │ └─ 1건+ → 렌더 건너뜀. 기존 .md 파일 그대로 사용 │ 동일 레포의 진행 중 세션 프롬프트를 깨지 않기 위함 │ │ ③ memory_snapshots INSERT │ (session_id, rendered, char_count, created_at) │ → 이 세션이 "무엇을 보고 있었는지"의 감사 기록 │ ▼ opencode serve :5552 │ opencode.json instructions[] 를 읽어 시스템 프롬프트 조립 │ - workspace/.config/opencode/AGENTS.md (기존) │ - workspace/.memory/global/USER.md (신규) │ - workspace/.memory/global/MEMORY.md (신규) │ - workspace/.memory/repos/<repoId>/MEMORY.md (신규) ▼ 시스템 프롬프트 확정 — 이 세션이 끝날 때까지 불변

②의 flush barrier가 이 절의 핵심입니다. 레포 단위로 활성 세션이 하나라도 있으면 렌더를 미룹니다. 세션 A가 대화 중인데 세션 B 시작 때문에 .md가 갱신되면, A의 다음 요청에서 시스템 프롬프트가 바뀌어 prefix cache가 통째로 깨집니다. 세션당 배타 파일을 만드는 방법도 있지만 instructions[] 경로가 세션마다 달라져야 해서 opencode.json을 세션마다 다시 써야 하고, 그 자체가 더 큰 경합을 만듭니다.

주입 시점의 함정: instructions[]에 존재하지 않는 경로가 있으면 OpenCode가 조용히 무시하거나 기동에 실패할 수 있습니다. 백엔드 부트스트랩의 ensureMemoryFiles()에서 빈 헤더만 있는 .md를 미리 생성해 두세요. 메모리가 0건이어도 파일은 항상 존재해야 합니다.

4.2 에이전트 자가 메모리 쓰기

세션 진행 중 — 사용자: "앞으로 이 레포는 pnpm만 써" │ ▼ opencode 에이전트 memory 툴 호출 판단 │ memory(action='add', target='repo', content='pnpm 전용. npm은 preinstall에서 실패') ▼ plugin/memory.ts │ POST http://localhost:5002/api/memory/write │ { action, target, content, old_text?, directory, sessionID } ▼ routes/memory.ts → memory-store.ts │ │ ① directory → repo_id │ ② 보안 스캔 시크릿 패턴 / 인젝션 패턴 / 중복 │ └─ 위반 → 400 + 사유. DB 미변경 │ ③ 예산 검사 현재 + 신규 > 2,200자? │ └─ 초과 → 아래 에러 형태로 반환 │ ④ memory_entries UPSERT ← DB는 여기서 즉시 반영 │ ⑤ 레포에 dirty 플래그 표시 (flush 대기열 등록) │ ⑥ .md 파일은 건드리지 않음 ▼ 툴 응답 → 에이전트 { "success": true, "usage": "1,612/2,200", "rendered_preview": "..." } │ └─ 에이전트는 툴 응답으로 자기 수정 결과를 인지한다. 시스템 프롬프트는 여전히 세션 시작 시점 그대로다. → Hermes의 frozen snapshot 의미론과 정확히 동일 │ ▼ Frontend SSE로 Memory 탭 배지 갱신 (읽기 전용 표시)

예산 초과 응답은 에이전트가 스스로 정리할 수 있도록 현재 상태를 동봉해야 합니다. 단순 실패 메시지만 주면 모델이 같은 쓰기를 반복 시도합니다.

{
  "success": false,
  "error": "Memory at 2,100/2,200 chars. Remove or replace an entry first.",
  "usage": "2,100/2,200",
  "current_entries": [
    { "id": 12, "content": "pnpm 전용. npm은 preinstall에서 실패", "hit_count": 8 },
    { "id": 31, "content": "구 CI는 node 18 고정 (2024-11 폐기됨)", "hit_count": 0 }
  ]
}

hit_count를 함께 주는 이유는, 어떤 걸 버릴지 판단할 근거가 그것뿐이기 때문입니다. 0에 오래 머문 엔트리가 1순위 후보입니다.

4.3 학습 루프 (session.idle 트리거)

턴 진행 중 — 훅 이벤트 적재 command-hooks.ts / bash 툴 실패 / git commit │ INSERT hook_events(reviewed_at=NULL, turn_index, exit_code, stderr_tail, cwd) ▼ SSE session.idle → proxy.ts tap → review-worker │ │ ⓪ 재귀 가드 이 세션이 curator 세션인가? │ └─ 예 → 즉시 종료 (curator도 idle을 발생시킨다) │ │ ① 게이트 질의 │ SELECT * FROM hook_events │ WHERE session_id=? AND reviewed_at IS NULL │ ├─ 0건 → ⑦로 직행. LLM 호출 없음 │ └─ N건 → 계속 │ │ ② 컨텍스트 조립 각 이벤트 turn_index ±3턴 │ - 겹치는 윈도우는 병합 (중복 토큰 제거) │ - 훅 사실(exit_code/stderr/cwd)을 구조화 필드로 첨부 │ - 전체 세션 다이제스트를 만들지 않는다 │ │ ③ memory-curator 호출 │ agent/memory-curator.md · 저비용 모델 │ 헤드리스 세션 · 재귀 가드용 태그 부착 │ 기존 코어 메모리를 함께 전달 (중복 제안 방지) │ │ ④ JSON ops 파싱 + 검증 │ 파싱 실패 → 1회 재시도 후 폐기. 부분 적용 금지 │ 각 op: { action, target, content, old_text?, rationale } │ │ ⑤ 보안 스캔 + 예산 시뮬레이션 │ 전부 적용했을 때 예산 초과면 rationale 우선순위로 절삭 │ │ ⑥ 분기 │ writeApproval=on → memory_pending + UI 배지 (기본값) │ writeApproval=off → memory_entries 즉시 커밋 │ UPDATE hook_events SET reviewed_at=now() │ │ ⑦ flush barrier 재검사 (§4.1 ②와 동일 질의) │ 레포 내 전 세션 idle → snapshot-renderer 실행 │ 아니면 dirty 유지, 다음 idle로 이월 │ │ ⑧ [6단계] 스킬 승격 후보 스캔 │ SELECT name, count(*) FROM hook_events │ WHERE repo_id=? AND exit_code!=0 GROUP BY name HAVING count(*)>=3 │ → pending 스킬 diff로 스테이징 ▼ .memory/*.md 갱신 — 다음 세션부터 반영
단계실패 시 처리
① 게이트훅 없음이 정상 다수 케이스. 조용히 종료하고 로그를 남기지 않는다 (노이즈)
③ curator 호출타임아웃/에러 시 reviewed_at을 갱신하지 않는다. 다음 idle에 재시도
④ 파싱부분 적용 금지. 전체 폐기 후 reviewed_at은 갱신 (무한 재시도 방지)
⑤ 스캔op 단위 거부. 나머지는 진행
⑦ flush실패해도 DB는 이미 정합. 다음 idle에 자연 복구
재귀 가드는 선택이 아닙니다. curator를 OpenCode 세션으로 돌리면 그 세션도 session.idle을 발생시키고, FTS 인덱서는 curator의 대화까지 인덱싱합니다. 가드가 없으면 리뷰가 리뷰를 부르는 루프가 되고, 검색 인덱스는 curator의 자기 독백으로 오염됩니다. 세션 메타데이터에 태그를 박고 ⓪과 fts-indexer 양쪽에서 걸러내세요.
왜 idle에 전부 몰아넣는가. 세 흐름의 부작용(파일 쓰기, LLM 호출, 인덱스 갱신)이 전부 한 지점에 모입니다. 턴 중간에 아무것도 변하지 않으므로 캐시가 안전하고, 문제가 생겼을 때 재현 지점이 하나뿐입니다. 대신 idle 핸들러가 무거워지므로 반드시 비동기로 띄우고, 실패가 세션 상태 전이를 막지 않게 격리하세요.

5. 리트리벌 흐름 (길이 문제의 실제 해법)

데이터 소스를 바꿔서 짧아지는 게 아니라, 점진적 공개로 짧아집니다. Hermes 스킬의 L0/L1/L2를 검색에 그대로 적용합니다.

에이전트 질의: "CORS 에러 어떻게 고쳤더라" │ ├─ L0 git_commits_fts bm25 상위 5 · subject + 파일경로만 │ → "a3f21c fix: preflight OPTIONS 허용 (src/cors.ts) · 3일 전" ~150 tok │ ├─ L0' session_messages_fts snippet(±40토큰) 상위 5 │ → "…Access-Control-Allow-Headers 누락이었고 …" ~250 tok │ ├─ L1 commit_detail(sha) git show --stat + 링크된 세션 턴 범위 │ → 변경 요약 + 그때 대화 3턴 ~800 tok │ └─ L2 git show <sha> diff 원문 (에이전트가 명시 요청할 때만) 가변

L0 두 갈래를 동시에 던지고 합쳐서 400 토큰 안쪽으로 끝내는 게 기본 동작입니다. L1 이상은 에이전트가 sha나 message_id를 들고 두 번째 호출을 할 때만 발생합니다. 인덱스에 diff 본문을 넣지 않는 이유도 여기에 있습니다 — DB만 레포 크기만큼 부풀고 정확도는 파일 경로 인덱싱 대비 개선이 미미합니다.

노출 툴

툴동작계층
session_search(q, repo?, k=5)FTS5 snippet 반환. message_id 포함L0'
session_expand(message_id, ±n)해당 턴 전후 원문L1
commit_search(q, repo?, k=5)커밋 메타 검색. sha 포함L0
commit_detail(sha)--stat + commit_sessions 조인 대화L1
memory(action, target, content, old_text?)코어 메모리 add/replace/remove1

6. 쓰기 경로 — 두 갈래

즉시 쓰기 · memory 툴

에이전트가 대화 중 판단해 직접 호출. 추가 LLM 호출 0, 컨텍스트 완전. "앞으로 pnpm 써" 같은 실행 없이 말로만 오는 규칙을 잡는 유일한 경로입니다.

배치 리뷰 · 훅 게이트

session.idle 무조건 실행이 아니라 hook_events에 미리뷰 항목이 있을 때만 기동. 컨텍스트는 turn_index ± N턴으로 한정.

훅 게이팅을 택한 이유는 입력 품질입니다. post-hook은 exit code, stderr, cwd, 소요시간을 기계적으로 검증된 사실로 넘깁니다. 전체 세션 다이제스트는 모델이 "사용자는 Vitest보다 Bun test를 선호하는 듯"처럼 검증 불가능한 추측을 만들어내고, 그게 영구 메모리에 박히는 게 최악의 실패 모드입니다.

Hermes가 전 턴 리뷰를 도는 건 개인 비서라서 잡담이 곧 선호도 데이터이기 때문입니다. opencode-webui는 코딩 워크벤치라 대화 대부분이 그 세션에서 끝나는 일회성 코드 논의입니다. 트리거 정책을 그대로 복사하면 안 됩니다. 전체 세션 리뷰는 설정으로 남기되 기본 off.

리뷰 루프 시퀀스

command-hooks.ts / bash 툴 실패 / git commit │ INSERT hook_events(reviewed_at=NULL) ▼ SSE session.idle │ ▼ review-worker 1. SELECT hook_events WHERE session_id=? AND reviewed_at IS NULL 2. 없으면 → 종료 (LLM 호출 없음) 3. 있으면 → 각 이벤트 turn_index ±3턴 + 훅 사실을 다이제스트로 조립 4. memory-curator 에이전트 호출 (저비용 모델, registry의 agent/ 사용) 5. 11. 지뢰

rebase / squash merge에서 sha가 사라집니다. commit_sessions 조인 실패는 에러가 아니라 정상 케이스로 처리하세요. squash는 특히 아파서, 여러 커밋의 세션 링크가 한 sha로 뭉개집니다. (repo_id, committed_at) fallback 인덱스를 이중으로 둬야 복구 가능성이 생깁니다.
prefix cache 무효화. 세션 진행 중 .md를 건드리면 시스템 프롬프트가 바뀌어 캐시가 깨지고 비용이 뜁니다. flush는 반드시 session.idle에서만.

그 외: opencode.json에 절대경로가 커밋되지 않도록 .git/info/exclude 처리, 멀티 라이터 동시성은 DB 트랜잭션 + 레포 스코프로 차단, 고정 토큰 예산(요청당 1,500–2,000 tok) UI 노출, 메모리 경유 프롬프트 인젝션 방지를 위한 쓰기 시 스캔, 한글은 tokenize='trigram' 없으면 부분일치 실패.
